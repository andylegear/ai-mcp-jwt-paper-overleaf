\section{Introduction}\label{sec:introduction}

The Model Context Protocol (MCP)~\cite{anthropic2024mcp} is increasingly used to
connect Large Language Models (LLMs) with external tools and
services~\cite{guo2025measurement,nsa2026mcp}. In a typical deployment, an LLM
orchestrator selects tools and produces structured calls whose arguments may
carry values from one tool invocation to the next. This arrangement is useful
for multi-step workflows, but it can place an LLM on a path that was
traditionally handled by deterministic software components.

\revjb{This relay path} carries opaque cryptographic credentials, including JSON Web
Tokens (JWTs)~\cite{rfc7519,rfc7518}. These values are not instructions for
the LLM to interpret; they are integrity-critical data that a downstream
service must receive unchanged. A single altered character can invalidate
cryptographic verification~\cite{rfc6750} and turn an otherwise valid tool
invocation into a hard authentication failure. The resulting fault is
operationally significant: the affected tool call fails, there is no
meaningful near-miss credential, and format checks may not reveal every
corrupted value before it reaches the downstream API. This is an
architectural problem rather than an instruction-following problem:
established credential-propagation patterns assume the relaying component
preserves the value exactly, but an LLM is a probabilistic component that
generates a new tool-call argument rather than acting as a transparent
transport channel, and prompt instructions do not create a deterministic
integrity guarantee. In privacy-preserving architectures where authentication
and signing occur locally and the resulting credential must be relayed
through an LLM orchestrator to a remote API~\cite{anonymous2026issre}, this
failure mode is directly exposed.

Existing work has examined unreliable LLM output, secret memorisation, and
security risks in LLM-integrated systems~\cite{huang2025hallucination,
ji2023hallucination, nie2025decoding, abadeh2026mcp}. These contributions are
important but do not characterise the runtime integrity of a novel credential
relayed through a live LLM tool chain, nor do they provide a reference
architecture for removing that credential from the inference path. We
therefore study the prevalence, character, and mitigability of JWT relay
corruption, and evaluate an architectural response \revjb{we call the Credential
Interception Vault}.

We advance the following research proposition:

\begin{quote}
\textit{For MCP deployments that would otherwise relay cryptographic
credentials through LLM inference, prompt-engineering mitigations are
insufficient to establish byte-exact relay integrity under current frontier
models. A deterministic architectural bypass that removes the credential from
the inference path eliminates this direct relay failure mode in the studied
systems, independently of the LLM used.}
\end{quote}

We structure the investigation around three research questions:

\begin{itemize}[itemsep=1pt,parsep=0pt,topsep=2pt]
  \item \RQ{1}: How prevalent is JWT corruption in LLM-mediated MCP relay, and
    how does it vary across the frontier model landscape?
  \item \RQ{2}: What forms does JWT corruption take, and how are corruption
    events distributed across credential structure and length?
  \item \RQ{3}: To what extent can prompt-engineering mitigations reduce JWT
    corruption, and why do they not establish an integrity guarantee?
\end{itemize}

Motivated by these findings, we further present and validate \revjb{this
architecture}, \revjb{which removes} the credential
from the LLM inference path and eliminates the direct relay failure mode by
construction (Sections~\ref{sec:reference_architecture}--\ref{sec:case_study}).

This paper makes seven contributions:
\begin{enumerate}[itemsep=1pt,parsep=0pt,topsep=2pt]
    \item An empirical characterisation of JWT relay fidelity across 16
      frontier LLMs in 48{,}000 controlled \revjb{tool-chain} runs, producing a cross-model
      defect rate ranking (\Contrib{1}).
    \item A failure taxonomy distinguishing six outcome types with
      security severity ordering (\Contrib{2}).
    \item A corruption characterisation identifying length-related and
      credential-segment concentration patterns, providing empirical evidence
      \revjb{for prioritizing which credential-relay patterns warrant further
      mechanistic investigation} (\Contrib{3}).
    \item An evaluation of prompt-based mitigation showing that the tested
      explicit production instruction does not eliminate corruption (19.9\%
      residual \DFR{} under production instruction conditions) (\Contrib{4}).
    \item The Credential Interception Vault, a model-agnostic reference
      architecture that removes credentials from LLM inference and thereby
      eliminates direct credential relay by construction (\Contrib{5}).
    \item An industrial case study validating the architecture in a
      production blockchain trading system (\Contrib{6}).
    \item An open replication package (\Contrib{7}).
\end{enumerate}
\revjb{The primary goal of this work is to determine if the failure occurs at a
meaningful rate and to identify an architectural solution that eliminates
direct credential relay; causal attribution of the underlying mechanism is
identified as a direction for future work} (Section~\ref{sec:conclusion}).
